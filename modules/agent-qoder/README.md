# agent-qoder — experimental standalone controller

Real v1 adapter for **Qoder CN standalone**, not IDE/Work/Wake/CLI. Product identity and each operation's necessary preload methods are checked; versions are bounded diagnostics, not an eligibility whitelist. Missing or failed version diagnostics return null without blocking an otherwise available operation. The installed 0.4.2/0.4.3 used contracts were compared statically; this is not a runtime pass or a promise for every version. Source compatibility and each installed runtime revision require separate acceptance. Internal preload APIs use explicitly enabled loopback CDP; this is not an official stable control protocol. No credentials, native database writes, automatic launch/restart, generic eval/shell, model switching, or implicit task creation.

| Operation | Kind | Arguments |
|---|---|---|
| launch | act | `{executable,debugPort?}`; explicit product/source-verified standalone start, or non-destructive existing-instance status |
| identity | read | `{}` |
| list_tasks | read | `{limit?:1..100,offset?:0..10000}`; non-archived |
| models | read | `{}`; live catalog, does not change selected model |
| search_task | read | `{sessionId,query,limit?:1..100}`; native message/turn IDs and snippets |
| queue_status | read | `{sessionId}`; local outbound queue states, no prompt body; requires operator workspace/root/deliveryDir |
| recover_queue | act | `{}`; start the provider-owned recovery worker after Core/Qoder startup or restart; does not create a message |
| read_interactions | read | `{sessionId}`; requires operator workspace/root; pending contents and exact review snapshots, not full history |
| respond_permission | act | `{sessionId,toolUseId,decision:"allow"|"deny",expectedSnapshot}`; exact snapshot returned by read_interactions, up to65536 characters |
| send | act | `{sessionId,requestId,correlation?,prompt}`; UUID IDs, optional shared-contract correlation, prompt up to8000 characters |
| send_new_session | act | `{sessionId,requestId,correlation?,prompt}`; first message creates a session; caller supplies fresh UUIDs before dispatch |
| interrupt | act | `{sessionId}`; request only, observe status afterwards |

`agent-module.json` / `adapter.mjs` implement the shared contract. Runtime needs only Node24 builtins and these two files plus `desktop.mjs`, `worker.mjs`, `config.mjs` and `launch.mjs`. Do not package `work/` (probe history, delivery markers and diagnostics) as executable runtime or automatically copy them to another machine. Never discard active delivery markers during an update.

## Operator configuration

Default file: `~/.codex-agent-core/agent-qoder.json`, beside the base's default registry. The module reads it on **every call**, so updating it does not require reopening Codex or changing the MCP launch environment. Import, metadata and `describe()` do not read it. A missing file does not create anything or start Qoder. A present invalid JSON/object, unknown field or invalid value fails explicitly, even if an environment override could conceal the invalid file. Only these six fields are accepted:

| JSON field | Explicit environment override | Requirement |
|---|---|---|
| cdpPort | QODER_DESKTOP_CDP_PORT | Integer1–65535; required for live transport; no port scan |
| workspaceId | QODER_CONTROL_WORKSPACE_ID | Native workspace UUID; required for mutations and read_interactions |
| root | QODER_CONTROL_ROOT | Authorized absolute cwd; required for mutations and read_interactions |
| deliveryDir | QODER_DELIVERY_DIR | Trusted persistent absolute marker directory; required for send and respond_permission |
| returnModulePath | none | Optional absolute path to the accepted receiver `native-turn-return.mjs`; configure with returnDataDir |
| returnDataDir | none | Optional absolute receiver data directory; configure with returnModulePath |

The first four fields allow the listed environment overrides; the two return fields are file-only. Empty/invalid overrides fail rather than falling back. General reads can configure only cdpPort; read_interactions additionally requires scope. Each invocation resolves its own snapshot and passes it to the desktop bridge; production code never injects values into `process.env`. These settings cannot be supplied through tool arguments. `config.example.json` is a placeholder-only example, **not** a real workspace binding; the operator must supply actual approved values. No real user configuration is created by this module or its tests.

Mutations check the operator workspace/root; `send` also checks its existing native session, while `send_new_session` checks the native workspace and that its requested session ID is absent from paged session lists. Both sends reserve the same SQLite queue and exclusive delivery marker **before** native dispatch. The queue stores prompt bodies in plaintext in the trusted deliveryDir; protect that directory with operator-only filesystem permissions. It has a 500-record total cap and no pruning. `queue_status` does not return prompt bodies. Its `dispatching` state reports `liveness:"unknown"`: it may be a normal in-flight call or a stale crash record, never an automatic replay signal. Reusing a request UUID never resends, even after crash, timeout or a pre-send rejection. Read the task's native evidence; do not invent a new request ID merely to bypass uncertainty. Keep deliveryDir stable across configuration updates/processes/restarts. Marker presence means reserved/unknown, not acceptance or completion.

The canonical real path of `send-queue.sqlite` deterministically identifies its persistent owner; extended-prefix and junction/symlink aliases resolve to the same owner, while a persisted `queue_meta` identity rejects a moved/hard-linked database under a different path. The owner is not a caller, PID or registration identity. The first accepted permission reservation establishes this same identity in its budgeted transaction but creates no sends/worker schema. Each accepted send returns the original result plus a Core schema-v1 `messageReceipt` with stable request/delivery/owner/target/correlation fields. If correlation is omitted it defaults to requestId. Configure Core's shared message budget with the `ownerId` reported by `queue_status` before sending. The worker accepts explicit legacy 20,000,000/200,000,000-byte totals and adaptive allocations, validates the sum and optional global cap, and preserves the explicit owner allocation. A larger platform total does not enlarge Qoder's quota. New writes fail explicitly when no allocation exists or this owner is unallocated/over quota. Schema creation/migration, legacy correlation backfill and the requested write share one `BEGIN IMMEDIATE`; budget rejection rolls all of them back. Existing records and protection markers are never pruned to make room; duplicate request lookups remain available while new writes are blocked.

All queue writes (including ACK/terminal observation and worker leases) use DELETE journaling, disabled cache spill and memory-only temporary storage. WAL and auto-vacuum databases are unsupported and are not silently converted. Before any SQLite connection or schema query, both read and write paths reject an existing `-wal`/`-shm` sidecar or WAL file-format bytes 18/19 in the main header; opening a WAL database just to inspect its mode can itself create a 32KiB SHM file. Before BEGIN, again under the write lock before DDL/DML, and before COMMIT, the guard reserves physical managed bytes plus dirty main-file growth (`page_count × page_size - current main bytes`) plus a conservative full projected database journal (`page_count × (page_size + 8) + 131072`). Existing journals and queued/dispatching marker bytes are deliberately counted again. The extra 131072 bytes cover two maximum 64KiB journal-header/padding sectors. Thus COMMIT cannot surprise a stat-only check with cached pages. This sacrifices roughly half usable capacity (up to roughly two-thirds with a large existing journal), adds at least 128KiB overhead and keeps dirty pages in RAM. A 9000-byte allocation cannot initialize a queue; the tiny-message offline fixture's highest required reservation was 185013 bytes, not a universal fixed minimum. `queue_status` reports current usage, not the additional write-peak headroom.

The bound covers module-managed DELETE-mode SQLite transactions on the tested Node24 SQLite runtime, with stable allocation and no outside writers changing the files. It is file length accounting, not filesystem allocation blocks or a RAM cap. Power-loss recovery/custom VFS behavior and arbitrary external writers are not validated. Permission reservations now use this same owner and SQLite write lock: their exact UTF-8 file bytes are added to the conservative SQLite peak before the exclusive `wx` write and native response. If a later ACK/state or lease write is budget-blocked, the protected reservation remains unknown/blocked; it is not pruned or replayed. The public physical-budget test retains the measurements without user runtime records.

The long-lived Core host keeps the existing watcher. After a host/Qoder restart, call mutating `recover_queue` once; it starts one detached provider worker guarded by a SQLite lease. The worker renews and verifies the same token around every session and immediately before marker/native side effects, observes exact previously sent turns and dispatches only an unambiguously queued head. FIFO release and native return both use the same strict normalized-history proof; a running session, pending interaction, unfinished tool or missing completion timestamp keeps the head awaiting_observation. A completed turn additionally needs its final root text; failed/interrupted do not. With the optional receiver pair configured, the same worker projects exact terminal facts to the receiver's internal function; a pending verified result keeps that worker active until proof or binding expiry. Version does not establish proof: missing finality fields still return no verified result. Facts use `evidenceSource="qoder-cn:normalized-history"` and carry `productVersion` only as a diagnostic. The ordinary watcher uses the same projection after observation. The returned `assistantId` is Qoder's normalized `assistant:<requestId>` ID, not a raw transcript UUID. `dispatching`, transport-unknown and `needs_attention` heads are never replayed. Without a pending return, the worker exits when no queued/awaiting head remains, on budget block, or when its registration generation is disabled, uninstalled or replaced. Reads never start it. Core currently has no module-start callback, so invoking `recover_queue` at startup/restart is the explicit lifecycle boundary; no extra business message is needed.

Only `agent-core`'s operator controls registration/installation. Check the deployed revision before claiming that this source is installed. Core reads metadata without opening Qoder and loads this adapter on selected discovery. CDP must already belong to the intended trusted local standalone instance. Localhost discovery is not authentication against another malicious local process; do not expose the endpoint remotely.

## Reviewed one-shot permission responses

Read first, review the **entire** native input and its effects against the user's actual task authorization, then explicitly respond to one toolUseId using the returned expectedSnapshot. The snapshot binds session/workspace/cwd, active turn, interaction type/ID/tool/input/request time. The module rereads the pending interaction and requires an exact snapshot match; changed/expired requests, missing active turns and wrong scope fail closed. No bulk approval or automatic continuation. A changed object key order also fails conservatively: obtain and review a fresh snapshot rather than editing one by hand.

Supported ordinary tool names: Read, Write, Edit, MultiEdit, Bash, PowerShell, Glob, Grep, LS. Other names, userQuestion, plan approval and special account/credential/PAT authorization are not supported for responses (they can be observed). Only allow/deny is forwarded; suggestion IDs, updatedInput, grantType and arbitrary fields are rejected. An allow keeps the native original input and grants no session/permanent rule or permission-mode change.

The fixed workspace/root identifies the target task; **it is not a filesystem or command sandbox**. A Bash command can affect paths outside cwd, and a separately authorized reference Read can target a file outside root. This module does not parse shell text or decide safety. The caller must stop on requests outside its actual authorization, including credentials, dependency installation, system changes, real callbacks, unrelated writes, push/commit or permission changes where not authorized. Merely possessing a snapshot is not authorization.

Each response reserves `permission-<sha256(sessionId,toolUseId)>.json` with exclusive `wx` in the existing deliveryDir before transport. This filesystem-safe key is not an authentication token. The reservation is flushed before transport and shares the queue owner's budget/mutex with send and worker writes. Missing/unallocated/insufficient budget fails before creating the marker or contacting Qoder; an existing marker still returns `not-resent` without requiring fresh budget. Concurrent duplicates, changed decisions, errors, timeouts, crashes and pre-dispatch rejections never replay that same interaction; the marker remains reserved/outcome-unknown even after ACK. Do not delete it, move to another deliveryDir or change IDs to retry. Reconcile with native evidence. ACK means only the response call returned, not tool execution or task completion. Snapshot validation and native response are separate IPC calls, not an atomic compare-and-set; native unique pending IDs/type checks are the final stale-response guard.

read_interactions uses native openChatSession on the one scoped task, returns only interaction/control fields and does not mark-read or respond. Native detail loading can refresh derived projections (and hydration where applicable); it is not a raw storage read. The response path deliberately permits waiting-user; the existing send busy guard is unchanged.

## Explicit temporary launch

After checking exact process identity, no active work and no unsaved inputs, an authorized operator may use `agent_act/launch` or call:

```js
import { launchQoder } from './launch.mjs';
await launchQoder('D:/Programs/Qoder CN/.qoder-versions/0.4.2/Qoder CN.exe', { debugPort: 19327 });
```

The launcher verifies the absolute named executable, `resources/product.json` (`productId=qoder-cn`, `appId=com.qodercn.app`) and ASAR package (`name=qoder-cn`); package version is diagnostic only. Command names, `.qoder-cn`, PATH hits and IDE copies are not identity evidence. It preserves the process-local direct-network policy: no inherited proxy variables, Electron `--no-proxy-server`, no global/TUN/TLS/security-setting change. Omit `debugPort` (and `cdpPort` configuration) for an explicit direct launch with no debugging endpoint; a matching existing process then reports `connection.status="not-requested"`. An existing root process is never killed, duplicated or silently reused. When a control port is explicitly requested, it reports whether the exact loopback CDP flags are present. Those flags cannot be added after start: controlled application exit and explicit relaunch are required only when control is requested. The non-disruptive alternative is to leave it running and defer adapter access until the user's work is naturally closed. `state="spawned"` verifies only that the requested executable spawned; its `identity` is the on-disk package identity, not the final running process. An updater or launcher can hand off to another version. Verify the actual process path and call `identity` on its exact loopback CDP endpoint before any business operation. A missing fixed required method gives `Missing desktop interface: <fixed method>` before that operation's business calls; unrelated methods are not inventoried or required. After reading the summary, an explicit session model additionally requires the live model-catalog method, while a null native default does not. Native rejection/transport failure remains subject to existing reservation and no-replay rules; changing a version never authorizes a retry.

## Evidence and limits

Autonomous queue dispatch through agent-core requires the core version that passes the per-registration
`assertCurrent` context. Qoder binds each watcher to its registration/revision, checks current registry
state before a tick, after asynchronous observation and immediately before sending CDP, and terminates
revoked callbacks. Disable/uninstall/re-register from another process are detected; re-enabling does
not revive an old callback. No read operation recreates watchers. A native evaluation already sent may
still complete after revocation; this mechanism does not cancel in-flight provider work. Direct JS calls
without a host context remain standalone helpers and have no registry revocation guarantee.

`needs_attention`, crash-left `dispatching`, unknown legacy operations and scope mismatches stop the
watcher without rearming. The owner of an actual in-flight send wakes queued tails after its ACK.
Read failures on an otherwise observable head retain the one-second poll, with no queue release.

- Identity/list/models/search and a direct send round trip were live-tested. Subsequent isolated tests covered overlapping FIFO, multi-session/multi-turn returns and explicit same-registration crash recovery. See [tested scope](../../docs/compatibility.md); these do not prove automatic worker rebirth or every native terminal scenario.
- `interrupt` has an earlier same-application native-call receipt plus offline scope checks. Cancellation of a currently running successful generation was NOT retested just to manufacture a test case.
- Existing-session `send` preserves an explicit native model and requires it enabled in the live catalog. A summary with `model:null` omits the model so Qoder resolves its own selected/default model; a null permission mode is omitted in the same way, without version-specific behavior. It does not choose a replacement model. Missing model still rejects. If a product no longer accepts an omitted override, its native error is not retried with a guessed replacement. `send_new_session` omits model and permission overrides so Qoder resolves defaults; both use requestId as native inputId and turnId. Distinct requests are atomically queued FIFO per session; sessions remain independent. After an accepted dispatch, the already-running agent-core host keeps one unreferenced watcher for that session. It reads the blocked head with native `loadChatHistoryAround` and calls the same `verifyNativeTurn` proof used for returns before recording the terminal outcome or releasing a successor. A terminal outcome (`completed`, `failed` or `interrupted`) requires the exact completed user/root assistant pair, completion timestamp and finished tools; completed additionally requires its final root text. Running/pending native state keeps the head blocked. Missing optional summary fields are not promoted to required fields. ACK, idle, timeout, Hook Stop and latest summary alone never release. Observation loss keeps polling without dispatch; `dispatching` after crash and `needs_attention` remain blocked and never replay. Cross-process watchers may coexist, but SQLite claim ownership permits one dispatch. `queue_status` stays read-only. The watcher relies on the existing long-lived host; a host restart preserves no-replay state but does not recreate timers until a later mutating module call.
- Mutation lookup checks the first100 non-archived tasks and fails closed if the target is absent. Extend native task lookup only when a real workload requires it; never infer a missing task should be created.
- Native send ACK is not completion. `search_task` correlates exact returned content by messageId/turnId; use list status separately. Search is not a complete transcript export.
- Startup cached model list can be empty while live catalog and execution work. Do not diagnose account denial merely from the UI's `qfmodel` warning.
- Interaction operations have offline exact-snapshot/no-replay tests and an installed native bridge MCP permission-response observation. This does not authorize unattended approval of arbitrary tool requests.
