Mail addresses are durable pull routes, not presence. Explicit native receiver connections add notifications where the product supports them. On 2026-10-11, independent scoped runtime review accepted Kimi ↔ Codex fresh automatic notifications, actual message fetches, correlated replies and exact confirmations. This does not certify every provider: a recipient's business refusal or native approval remains distinct from transport delivery. Qoder/ZCode may select mail even with dedicated adapters installed. Mail never mirrors an accepted product message or silently retries an uncertain native send through another channel.

On 2026-10-12, Yuan's native-local Codex creation and first reply were accepted in an isolated case; its eight-tool cloud catalog was observed separately. QoderWake source7 passed independent affected source/offline review, with installed parity and a native read-only adjacent-cursor check. Earlier scoped native cases cover creation, same-Session follow-up, bounded current-turn replies and a real interrupt. Full Conversation/mention/claim/RunTrace control and all terminal states remain outside that acceptance. The shared post-core-mail skill passed isolated native CLI consumption tests; that does not certify adoption by all existing sessions.

ZCode CLI mail is link-free; existing desktop session control still uses Sharing Link. IDE control is page-level, not atomic native-session targeting; a pre-switch observation does not certify simultaneous click races. Explicit recovery does not prove autonomous restart or every terminal state. Partial active counts do not establish complete inventory/global idleness.

Qoder's native sends reuse the existing queue and native login; CLI/SDK operation does not require a visible desktop window. Automatic resume currently covers managed-writers-only sessions; a Core-created session and two history-tail checks are not an atomic global lock. The installed desktop has its own message projection; normal open does not import newer external CLI history into an already populated message store. The initial 2026-10-09 UI observation therefore failed. The accepted and installed source4 bridge now uses the installed product's projection, serialization and search writer, configured by the paired operator `desktopDatabasePath`/`desktopArchivePath`, after exact native command/result/history verification. Real normal desktop search/open in standalone 0.4.3 then displayed both completed Core-created turns and the completed CLI continuation in the original desktop session; its old 13 rows remained unchanged and repeat projection inserted zero rows. Display-only completed Hook/fragment-ID/thinking-timing differences are ignored only for previous-prefix comparison; native content/tools/order/state and collision guards remain. No old requests were resent. An already-open page's automatic hot refresh is not implemented or claimed. Injection into an externally busy desktop process remains unsupported by the managed path. Unavailable CDP-only operations are not advertised, and an uncertain send is never retried through another transport. The optional compatibility skill uses the same Core path, not another sender.

The desktop open-path explanation received independent read-only review; the original runtime gate values were not captured, so it is not claimed as the unique runtime cause. SDK `sendHostAction` reports Host UI feedback to the CLI, not a desktop refresh command. `enableRemoteProjection` requires a remote-session identity and has not been shown to refresh the local desktop projection. Neither method was invoked as a substitute for the missing synchronization path.

The ZCode CLI test first hit a bundled provider-path resolver miss before any session/model/tool execution. Supplying the existing bundled provider path only to the isolated child corrected startup; credentials/models were not replaced.

Public offline checks run through `npm test`. Native events and queue records were reconciled locally. Personal transcripts, live bindings and raw logs are not distributed. [Component guides](../README.md#optional-integrations).
