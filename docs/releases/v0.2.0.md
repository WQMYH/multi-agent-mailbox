# v0.2.0 — Multi-Agent Mailbox / 多智能体信箱

## Added

- Local shared CLI/three-tool MCP mailbox: stable session registration, contacts, explicit recipients, correlated replies, durable fetch and exact ack.
- Configurable capacity: default 50,000,000 bytes per real persistent owner, optional default/owner/global limits, protected-data backpressure and retained allocations.
- Optional Qoder standalone/IDE and ZCode adapters, Qoder return ZIP, ZCode companion ZIP and IDE VSIX.
- Unified public offline tests/CI, bilingual README, compatibility, security and contribution guides.

## Native-tested agents

Codex, pi, Qoder standalone, ZCode CLI and OpenClaw have real generic-mail flow evidence. Qoder CN IDE has command/page/reply/status evidence; its own generic-mail loop is not separately claimed. Other CLI/MCP-capable agents are generally interface-compatible and may add a specialized native adapter when needed.

ZCode native CLI mail needs no Sharing Link. Existing ZCode desktop control is a separate route that still needs the link. Mail is pull-based, not automated wakeup.

## Fixes included

- Qoder FIFO requires verified finality, not weak terminal hints.
- ZCode workers retain the authoritative Core budget source and reject invalid/disabled registration.
- IDE non-page mutations use the same owner-budget admission as page actions.
- Legacy ZCode queue blocking/recovery-slot/missing-target corrections are retained.

## Upgrade

Repository: `WQMYH/Codex-with-Zcode` → `WQMYH/multi-agent-mailbox`. Component and `codex-with-zcode` marketplace IDs remain compatible. Codex marketplace now offers `agent-core`, not retired standalone `zcode-ops`. Preserve old data/unknown requests and register needed modules; do not downgrade or clear queues.

Node.js 24+ is required. Core/mail has no npm dependencies; root dependencies support legacy ACP diagnostics. Product versions are observations, not gates.
