# Events core: preflight only

This module does not register MCP methods, persist subscriptions, activate a subscription, send a request, or poll a mailbox. Its SOURCE_OFFLINE check is `node qoder-codex-bridge/scripts/mcp-events-test.mjs`; it is deliberately outside the existing package test command until the owner wires the feature. No new dependency or message queue was added.

The single candidate event is `codex.message.accepted`, filtered by exact `requestId` and `threadId`. It projects the existing `codex_message_status` result's persisted native-host ACK and original `acceptedAt`. It includes no message text, path, signing secret, reply, or business-completion claim. Event identity remains the same on retry; `cursor: null` explicitly offers no replay. An uncertain or missing receipt generates no event.

`createMcpEventsCore({ authenticate, authorize, readReceipt })` takes **internal service adapters**, never RPC arguments. `authenticate(context)` must derive a stable account/principal ID from a verified connection. `authorize(principalId, eventName, filters)` must return literal `true` only for an authorized event/resource; `filters: null` is catalog visibility. The core checks authorization on catalog, subscribe/unsubscribe preparation, and receipt projection. The service must additionally check account disconnection and temporary read-access expiry immediately before verification and application network sends. `readReceipt(requestId)` must use the existing validated persisted-receipt reader, not model-supplied status JSON. No default adapters exist. Fixed operator `_meta`, a body claim, a request ID, and a recipient's correlation prefix establish none of these permissions.

Core API:

- `list(context)`: authorized catalog only; it is not `server/discover`.
- `prepareSubscribe(context, params)` / `prepareUnsubscribe(context, params)`: validate filters, HTTPS URL syntax, canonical standard base64 `whsec_` secret of 24–64 bytes, no replay cursor, and requested lifetime; derive the same ID from principal + normalized callback + event + ordered filters. Secret rotation does not change identity. Subscribe returns an **internal candidate containing the secret**, never an RPC result or log value.
- `verification(candidate)`: signed single-use challenge with a 10-second limit; pass parsed bounded response JSON and actual HTTP status to `.verify(...)`. Echo comparison is constant time. This is verification evidence, not durable activation.
- `acceptedEvent(candidate)`: authorized metadata projection from the existing persisted receipt.
- `prepareDelivery(candidate)`: requires successful verification for this candidate, rechecks resource permission, and returns a signed POST packet, or `null`. It signs the serialized UTF-8 body once and returns those exact bytes. It performs no network request and does not assert an active/unexpired durable subscription. A rehydrated candidate must be reauthorized and verified.

Root integration gates, currently unresolved:

1. Establish actual authenticated Dot/Work-Cloud caller context on the same endpoint as tools. Current legacy stdio's operator does not establish a per-caller identity bridge. Do not advertise Events or MCP 2.0 `2026-07-28` support before the complete endpoint implements that protocol.
2. Provide a reviewed HTTPS transport that resolves and blocks private/local/non-public addresses **at each connection**, connects to the validated address, and preserves the original hostname for TLS verification. Apply this both to verification and application delivery; reject redirects. URL syntax and `redirect: error` in a packet are not SSRF protection. This module deliberately has no `fetch` fallback. Bound connection/response time and response bytes; map callback timeout to `-32015` / `data.reason: timeout`, and other verification failure to `challenge_failed`.
3. Persist principal, filters, callback, secret, granted expiration and delivery/verification facts atomically before activation, including across restart. Reuse the existing owner's budget and managed exclusive/atomic write helpers if using `dataDir`; account for subscription bytes and key rotation in that same real-owner quota. Do not return success if quota or persistence fails. Grant finite expiry for the present temporary authorization; honor requested `ttlMs` and stop when expiry or access revocation occurs. Handle refresh/rotation with a bounded old/new signature overlap, unsubscribe idempotently, and ensure an in-flight subscribe cannot reactivate an unsubscribed candidate.
4. Wire `events/list`, `events/subscribe`, and `events/unsubscribe`, then advertise through the official `server/discover` result. Only return the public subscription ID, granted `refreshBefore`, `cursor: null`, and `truncated: false` after successful activation. Apply filters before delivery; do not create a second message store or dispatch state machine. A metadata event cannot replace an actual reply event when testing bidirectional conversation.
5. Recheck durable active/unexpired status and authorization immediately before each send. Retry transient failures with bounded exponential backoff and fresh signing timestamps; preserve event ID and body, stop retries on 410/413. Track webhook receipt separately: HTTP 2xx proves neither Dot processing nor a recipient's response. Avoid feedback loops.

Recovery condition: Root supplies verified caller/authorization and reviewed transport/storage implementations, followed by independent source review and a real Dot subscription, signed challenge, delivery, visible Dot processing, filter rejection, and unsubscribe test. Offline preflight success cannot substitute for any of these gates.

Reference: [official OpenAI MCP Events documentation](https://developers.openai.com/plugins/build/mcp-events), retrieved 2026-10-10. The pure signing/packet tests validate bytes locally; they do not prove live Standard Webhooks or Tunnel interoperability.

## HTTPS transport candidate

`mcp-events-transport.mjs` adds `createMcpEventsTransport({ lookup, request })`; the optional **internal** I/O seam defaults to Node's `dns/promises.lookup` and `https.request`. Calling the returned function as `transport(packet, { assertActive })` makes one HTTPS POST and returns `{ status, ok, body }`, with `body` a bounded UTF-8 response string. After all DNS answers pass address validation, but before creating an HTTPS request, it awaits the internal `assertActive()` hook and requires literal `true`. Rejected, invalid, or throwing guards yield only `webhook_grant_inactive`. The original 10-second deadline covers the hook, and late completion cannot create a request. Runtime must pass this fresh permission/expiry/unsubscribe/key-rotation guard for **every challenge and application delivery**; never obtain it from RPC parameters. The compatible one-argument helper performs no authorization check and grants no permission. It never retries, follows redirects, logs content, stores a subscription, or parses/reserializes the signed request body. The same function handles verification packets; parse its bounded response and pass the actual status to the core's challenge verifier.

Each call resolves all A/AAAA answers with `all: true`; any invalid or prohibited answer rejects the complete destination before an HTTPS request exists. Public IP literals undergo the same address policy without DNS. It then connects directly to one validated literal IP, disables agent reuse/family fallback/environment proxy configuration, and preserves the callback hostname in TLS SNI, certificate hostname verification and HTTP Host. Certificate-chain validation is explicitly enabled. There is no second hostname resolution during connection and no fallback to another address. The body limit is 256 KiB, request/response headers are bounded, response body limit is 16 KiB, and one 10-second deadline covers DNS, connection, TLS, and response completion. A timed-out native DNS operation may finish later; the settled guard prevents that completion from creating an HTTP request.

The address policy conservatively rejects IPv4 special/private/link-local/shared/documentation/multicast/reserved ranges, permits IPv6 only within `2000::/3`, and rejects its IETF special-purpose, documentation and 6to4 subranges. This also rejects every IPv4-mapped IPv6, NAT64, ULA, loopback, scoped/link-local and multicast address. Some globally reachable special-purpose exceptions are deliberately rejected; revisit only for a verified callback need against the current IANA registries. Ordinary DNS/HTTPS is supported; custom proxy/CA configuration and alternate transports are not exposed.

`node qoder-codex-bridge/scripts/mcp-events-transport-test.mjs` uses only fake DNS/HTTPS I/O, checks actual Node certificate hostname matching against offline certificate metadata, and includes mixed DNS answers, DNS rebinding across calls, body/header protection, redirect rejection, size/deadline failures and a disposable `MCP_EVENTS_TRANSPORT_TEST_MUTATION=allow_private` negative control. This is SOURCE_OFFLINE evidence, not an actual DNS/TLS connection or Dot delivery. Upper layers must still prove the caller identity, check current permission/expiry immediately before sending, persist subscriptions within the real owner's budget, manage refresh/key rotation/unsubscribe races, validate the signed challenge, and implement bounded retries except on 410/413. HTTP 2xx remains webhook receipt only.

Transport policy sources: [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry), [IANA IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry), and [Node HTTPS](https://nodejs.org/api/https.html), [TLS hostname verification](https://nodejs.org/api/tls.html#tlscheckserveridentityhostname-cert), [address-family selection](https://nodejs.org/api/net.html#socketconnectoptions-connectlistener), retrieved 2026-10-10. Installed offline test runtime: Node 24.16.0.
